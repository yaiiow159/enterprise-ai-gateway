# 發版把關

```bash
node .claude/skills/release-check/check.js
node .claude/skills/release-check/check.js --full    # 加上壓測與多節點成本上限
```

前置條件：`dev-stack` 已啟動。腳本會自行建置並管理網關的啟停。
**阻擋**項目失敗時以非 0 結束，可直接接進 CI。

## 這支腳本自己不做任何驗證

每一項檢查都有自己的 skill、都能單獨執行。這裡負責的只有三件事：
**串起來、把關、留下紀錄**——也就是回答「交付之前有沒有漏跑哪一項」。

## 涵蓋的項目

| 項目 | 阻擋 | 來源 |
| --- | --- | --- |
| 版控狀態 | 否 | `git status` |
| 建置 | **是** | `mvn clean install` |
| 金鑰外洩掃描 | **是** | `secret-guard --self-test`（含全專案掃描）|
| 假 Provider 自我驗證 | **是** | `tools/fake-provider/smoke.js` |
| RAG 檢索品質 | 否 | `rag-eval` |
| RAG 檢查本身有效 | **是** | `rag-eval --self-test` |
| 成本風險 | **是** | `cost-guard`（靜態 + 執行期）|
| 串流轉發 | **是** | `stream-check` |
| 路由與對沖 | **是** | `tools/verify-routing.js` |
| 多節點成本上限 | **是** | `tools/verify-budget-multinode.js`（`--full`）|
| 壓測 | 否 | `bench`（`--full`）|

## 兩級嚴重度，但非阻擋不等於可以忽略

非阻擋項目一樣列在報告最前面，只是不讓 CI 變紅。分成兩級是因為**有些缺口是已知
且有意接受的**，不是因為它們不重要：

- **RAG 檢索品質**：專案目前還沒有 RAG 程式碼，所以它會如實報告「沒有東西可檢查」。
  但同一支工具的 `--self-test` 是阻擋項——**工具本身壞掉是另一回事**。
- **壓測**：量的是效能而不是正確性，而且受當下機器負載影響。
  數字留在報告裡讓人自己判斷，不該因為某次跑慢了就擋住發版。
- **版控狀態**：有未提交的變更不代表不能交付（可能正在準備 commit），
  但報告要說出來。

## 兩個刻意的設計

**每一項的完整輸出都留在報告裡。** 只寫「未通過」等於逼使用者重跑一次，
那這支腳本就只是多花一次時間。失敗當下也會立刻印出最後幾行，不必等到報告。

**網關生命週期集中管理。** `cost-guard` 與 `stream-check` 共用同一個已啟動的網關；
`verify-routing` 與多節點驗證則自己啟停（前者每個情境都要重啟以確保統計乾淨）。
切換之間會強制清掉殘留 JVM——殘留行程佔住連接埠時，下一項會靜靜地測到上一個實例。

## 目前的執行時間

不加 `--full` 約 2 分半，其中路由與對沖佔 95 秒（它為每個情境重啟網關，
那是它斷言正確性的前提）。`--full` 會再加上壓測與多節點驗證，約多 5 分鐘。
